# LiPi — Database

Authoritative database definitions for the LiPi HIS platform.

## Tiers

| Tier | Engine | Scope | Instances |
|---|---|---|---|
| Master Registry | PostgreSQL 16 | Tenants, subscriptions, global identity, AD federation | 1 per region |
| Per-Clinic OLTP | PostgreSQL 16 | One clinic's complete clinical & operational data | N (one per clinic) |
| Data Warehouse | ClickHouse | Group-head dashboards, MIS, Six Sigma rollups | 1 per region |

A clinic never queries another clinic's OLTP directly. Group dashboards read from the warehouse.

## Conventions (applied to every table)

- **PK** `UUID` generated by `core.uuid_v7()` (time-ordered for B-tree locality)
- **Tenancy guard** every per-clinic table carries `clinic_id UUID NOT NULL`; RLS policy enforces it as defense-in-depth
- **Audit columns** `created_at`, `updated_at`, `created_by`, `updated_by`, `deleted_at` (soft delete), `row_version INT`
- **Extension** `extension_data JSONB` on clinical entities (FHIR-compatible extensibility without schema churn)
- **Partitioning** monthly range partitioning on high-volume tables (`encounters`, `observations`, `audit_events`, `dicom_instances`)
- **Enums** `TEXT` with `CHECK` constraints — PG native ENUMs are too rigid to migrate
- **Codesets** lookup tables for ICD-10, SNOMED-CT, LOINC, RxNorm, populated from authoritative sources
- **Naming** `snake_case`, plural table names, FKs named `<ref_table>_id`, indexes `ix_<table>_<cols>`, constraints `ck_/fk_/uq_<table>_<name>`

## Running order

```
psql -f 00_common/*.sql          # once per DB cluster (extensions + shared functions)
psql -f master/*.sql             # once, on master DB
psql -f clinic/*.sql             # once per clinic DB (when a new tenant is provisioned)
```

For a new clinic, the provisioning worker runs `clinic/*.sql` against the newly-created database.
