> **Module**: Patient Registration  
> **Status**: 🟡 80% Complete — Active development  
> **Pages**: PatientNew, PatientEdit, PatientSearch, PatientQueue  
> **CSS Prefix**: `pn-` (PatientNew), `pe-` (PatientEdit), `ps-` (PatientSearch)  
> **CSS File**: `04-patient-registration.css` + `reg-*` system (PatientNew only)

---

## OVERVIEW

UHID-based patient registration with:
- Configurable UHID format per clinic (PT-YYYY-XXXXXX, optional Luhn check digit)
- Provisional UHID for internal use only
- Duplicate detection cascade: Aadhaar → ABHA → Name+DOB → Name+DOB+Mobile
- Multi-address (current + permanent), multi-contact
- Inter-clinic sharing via consent + encrypted FHIR R4 bundle
- Aspirational district auto-detection
- DOB confidence tagging (Verified / Self-reported / Estimated / Unknown / Overridden)
- DOB Verified can be overridden by SysAdmin OR SiteAdmin (marked "Overridden")

| Class | Purpose |
|-------|---------|

| `reg-lbl` | Label — 10px, 700 weight, uppercase |
| `reg-req` | Required asterisk — red |
| `reg-lhint` | Inline label hint — 9px muted |
| `reg-err` | Error span — 10px red, ALWAYS rendered |
| `reg-inp` | Text input — 34px height |
| `reg-sel` | Select — same as reg-inp |
| `reg-split` | Compound field wrapper |
| `reg-split-l/r/mid/end` | Compound segments |

### Critical Rules
- ✅ Every `reg-fg` MUST have `<span class="reg-err">&nbsp;</span>`
- ✅ Without it, grid rows misalign on errors
- ✅ Hints go inside labels using `reg-lhint`

## DUPLICATE DETECTION UI (CASCADE — Decision #6)

```
⚠️ Possible Duplicate Detected
─────────────────────────────────────────────────
Existing Patient                   Match Confidence
◯ Rajesh Kumar (PT-2025-001234)         98% ★★★★★
  DOB: 1980-05-15 · Aadhaar: ****1234
  [View Full Profile] [Same Patient]

◯ Rajesh K. (PT-2024-005678)            72% ★★★
  [View Full Profile] [Same Patient]
─────────────────────────────────────────────────
Or [Continue new registration] (requires reason)
```

### Cascade Order (LOCKED)
1. **Aadhaar match** → 98% (★★★★★)
2. **ABHA match** → 95% (★★★★★)
3. **Name + DOB** → 75-85% (★★★★)
4. **Name + DOB + Mobile** → 90% (★★★★★)

Override duplicate alert MUST capture reason. Audit logged.

## DOB CONFIDENCE TAGGING (LOCKED — Decision #5)

| Confidence | Use case | Badge | Editable? |
|-----------|----------|-------|-----------|
| **Verified** | Aadhaar/Passport confirmed | 🟢 "Verified" | Only by SysAdmin OR SiteAdmin (marks "Overridden") |
| **Self-reported** | Patient stated, no doc | 🟡 "Self-reported" | By any reception |
| **Estimated** | Approximate (elderly) | 🟠 "Estimated" | By any reception |
| **Unknown** | Cannot ascertain | 🔴 "Unknown" | By any reception |
| **Overridden** | After override of Verified | ⚫ "Overridden by [User] on [Date]" | Only SysAdmin/SiteAdmin |

### Override Flow
1. Modal: "Verified DOB will be marked 'Overridden'. Continue?"
2. Capture mandatory reason
3. On save:
   - Update DOB
   - `dob_confidence = 'overridden'`
   - `dob_overridden_by`, `dob_overridden_at` set
   - Audit event: `PATIENT_DOB_OVERRIDDEN`
4. Show "Overridden by [Name] on [Date]" badge permanently

## RECORD MERGE (LOCKED — Decision #7)

### Cooling-Off Periods by Role
| Role | Wait Time | Use Case |
|------|-----------|----------|
| Reception/Basic | 24 hours | Initiate merge request, await SiteAdmin approval |
| Staff (Nursing+) | 7 days | Approve merge if records similar |
| SiteAdmin | 30 days | Final approval for clinical records |
| SysAdmin | 30 days+ | Cross-clinic merges, complex cases |

Merge UI shows side-by-side comparison + reason field. Both records preserved (one marked merged_into).
