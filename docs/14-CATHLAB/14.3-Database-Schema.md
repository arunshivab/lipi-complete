## DESIGN PATTERNS (apply where relevant)

### Pattern 1: Patient References
If table references patients, ALWAYS use `entity_id`, NEVER `id`:
```sql
patient_entity_id UUID NOT NULL REFERENCES core.patients(entity_id)
```

### Pattern 2: Soft Delete
```sql
deleted_at TIMESTAMPTZ  -- NULL = active
```

### Pattern 3: Immutable (for clinical records)
Same pattern as core.patients — every change = new INSERT.

### Pattern 4: HIPAA Encryption
Sensitive fields encrypted at rest (AES-256-GCM):
- Patient identifiers (Aadhaar, ABHA, etc.)
- Insurance policy numbers
- Sensitive clinical data

2. ✅ **Explicitly configure non-conventional FKs** — avoid shadow column bugs
