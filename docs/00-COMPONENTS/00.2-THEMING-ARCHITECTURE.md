# 00.2 — Theming Architecture (Multi-Theme System)

> **Decision Reference**: BASE v1.0 #12 (Sub-Decision 12.4)  
> **v1.0 Ships With**: 1 brand × 2 modes = 2 themes  
> **Architecture**: Two-dimensional (brand × mode)  
> **Default**: `lipi-default-light`

---

## ARCHITECTURE OVERVIEW

LiPi HIS uses a **two-dimensional theme model**:

```
                  ┌─────────────────────────┐
                  │   LIGHT MODE   DARK MODE│
   ┌──────────────┼─────────────────────────┤
   │ LIPI DEFAULT │  ✓ v1.0       ✓ v1.0   │
   │ ARMOKI       │  ⏳ v1.1       ⏳ v1.1   │
   │ CLIENT 3     │  ⏳ v1.2       ⏳ v1.2   │
   └──────────────┴─────────────────────────┘
```

**Brand Theme**: Determines colors, logos, brand identity (set per clinic by admin)  
**User Mode**: Light/Dark/Auto/High-contrast (set per user)

Combined: `[brand]-[mode]` → e.g., `lipi-default-light`, `armoki-dark`

## CSS VARIABLE TOKEN SYSTEM

### Three Layers (Cascade in This Order)

```
LAYER 1: STRUCTURAL (00-baseline.css)
├── Defines: spacing, sizing, typography, border-radius
├── NO color values
├── References color tokens (e.g., var(--color-primary))
└── Always loaded

LAYER 2: BRAND (themes/brand-[name].css)
├── Defines: --brand-primary-hue, --brand-accent-hue
├── Defines logos, brand-specific assets
├── Loaded based on data-brand attribute on <body>
└── ONE brand active at a time

LAYER 3: MODE (themes/mode-[name].css)
├── Defines: actual color VALUES (resolves brand hues + mode)
├── Defines: --color-primary, --color-text, --color-bg, etc.
├── Loaded based on data-mode attribute on <body>
└── ONE mode active at a time
```

```
    ├── _theme-loader.css             ← Imports all themes (cascade order)

    ├── mode-light.css                ← Layer 3: Light mode VALUES
```

### Cascade Order in App.razor

```html
<head>
  <!-- Order matters! -->
  
  <!-- 1. Structural baseline (always loaded) -->
  <link rel="stylesheet" href="css/00-baseline.css?v=@AppVersion" />
  
  <!-- 2. Brand layer (one active at a time) -->
  <link rel="stylesheet" href="themes/brand-lipi.css?v=@AppVersion" />
  
  <!-- 3. Mode layer (BOTH loaded, activated by data-mode attribute) -->
  <link rel="stylesheet" href="themes/mode-light.css?v=@AppVersion" />
  <link rel="stylesheet" href="themes/mode-dark.css?v=@AppVersion" />
  
  <!-- 4. Component CSS (after themes so they can use tokens) -->
  <link rel="stylesheet" href="css/components/lipi-button.css?v=@AppVersion" />
  <!-- ... etc -->
  
  <!-- 5. Module CSS (last) -->
  <link rel="stylesheet" href="css/modules/01-user.css?v=@AppVersion" />
  <!-- ... etc -->
</head>
```

## THEME PROVIDER COMPONENT

### `Components/Theme/ThemeProvider.razor`

```razor
@implements IDisposable
@inject IUserPreferenceService PrefService
@inject IClinicContextService ClinicCtx
@inject IJSRuntime JS

<CascadingValue Value="@_currentTheme" Name="CurrentTheme">
    @ChildContent
</CascadingValue>

@code {
    [Parameter] public RenderFragment? ChildContent { get; set; }
    
    private ThemeContext _currentTheme = new();
    
    protected override async Task OnInitializedAsync()
    {
        var brand = ClinicCtx.CurrentClinic?.BrandThemeId ?? "lipi-default";
        var mode = await PrefService.GetThemeModeAsync() ?? "light";
        
        _currentTheme = new ThemeContext { Brand = brand, Mode = mode };
        
        // Apply to body
        await JS.InvokeVoidAsync("eval", 
            $"document.body.setAttribute('data-brand', '{brand}')");
        await JS.InvokeVoidAsync("eval", 
            $"document.body.setAttribute('data-mode', '{mode}')");
    }
    
    public async Task SwitchModeAsync(string newMode)
    {
        await PrefService.SetThemeModeAsync(newMode);
        _currentTheme = _currentTheme with { Mode = newMode };
        
        await JS.InvokeVoidAsync("eval", 
            $"document.body.setAttribute('data-mode', '{newMode}')");
        
        StateHasChanged();
    }
    
    public void Dispose() { /* cleanup */ }
}

public record ThemeContext
{
    public string Brand { get; init; } = "lipi-default";
    public string Mode { get; init; } = "light";
}
```

### Usage in App.razor

```razor
<CascadingAuthenticationState>
    <ThemeProvider>
        <Router AppAssembly="...">
            <!-- ... -->
        </Router>
    </ThemeProvider>
</CascadingAuthenticationState>
```

## DATABASE SCHEMA ADDITIONS

### New Column on `master.clinics`

```sql
ALTER TABLE master.clinics 
  ADD COLUMN brand_theme_id VARCHAR(50) NOT NULL DEFAULT 'lipi-default';

CREATE INDEX idx_clinics_brand_theme ON master.clinics(brand_theme_id);
```

### New Table: `clinic.identity.user_preferences`

```sql
CREATE TABLE identity.user_preferences (
  user_id        UUID PRIMARY KEY,           -- master.platform_users.user_id
  theme_mode     VARCHAR(20) NOT NULL DEFAULT 'light',
  density        VARCHAR(20) NOT NULL DEFAULT 'compact',
  font_size      VARCHAR(20) NOT NULL DEFAULT 'standard',
  language       VARCHAR(10) NOT NULL DEFAULT 'en',
  created_at     TIMESTAMPTZ DEFAULT NOW(),
  updated_at     TIMESTAMPTZ DEFAULT NOW(),
  
  CONSTRAINT chk_theme_mode 
    CHECK (theme_mode IN ('light','dark','auto','high-contrast')),
  CONSTRAINT chk_density 
    CHECK (density IN ('comfortable','compact','spacious')),
  CONSTRAINT chk_font_size 
    CHECK (font_size IN ('standard','larger'))
);

CREATE TRIGGER tr_user_preferences_updated 
  BEFORE UPDATE ON identity.user_preferences
  FOR EACH ROW
  EXECUTE FUNCTION update_modified_column();
```

```csharp

});
```

## TESTING REQUIREMENTS

### Visual Regression
For each component:
1. Screenshot in `lipi-default-light`
2. Screenshot in `lipi-default-dark`
3. Compare with previous build (Percy / Chromatic / manual diff)

### Contrast Ratio (WCAG AA)
All text on backgrounds must meet:
- Normal text: 4.5:1
- Large text (18px+): 3:1
- UI components: 3:1

Test with: https://webaim.org/resources/contrastchecker/

### Theme Switch Performance
- Mode switch: < 100ms (instant feel)
- No flash of unstyled content (FOUC)
- No layout shift
- Persists across page reloads

### Manual Test Checklist
- [ ] Toggle mode → all components update instantly
- [ ] Refresh page → mode preference persists
- [ ] Login as different user → their preference loads
- [ ] Different clinic → different brand applies
- [ ] All status colors visible in both modes
- [ ] All section accents visible in both modes
- [ ] Focus rings visible in both modes
- [ ] Disabled states distinguishable in both modes
- [ ] Loading states distinguishable in both modes

## SECURITY CONSIDERATIONS

- Theme preferences are NOT sensitive (no PHI)
- BUT: theme switching JS must not allow XSS
- Sanitize: never accept arbitrary CSS from user input
- Validate: theme_mode and brand values against allowlist

```csharp
// In UserPreferenceService
private static readonly HashSet<string> ValidModes = 
    new() { "light", "dark", "auto", "high-contrast" };

private static readonly HashSet<string> ValidBrands = 
    new() { "lipi-default", "armoki" };  // Updated as brands added

public async Task SetThemeModeAsync(string mode)
{
    if (!ValidModes.Contains(mode))
        throw new ArgumentException("Invalid theme mode");
    // ... save to DB
}
```
