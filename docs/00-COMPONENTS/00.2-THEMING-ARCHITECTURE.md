# 00.2 — Theming Architecture (Multi-Theme System)

> **Decision Reference**: BASE v1.0 #12 (Sub-Decision 12.4)
> **v1.0 Ships With**: 1 brand × 2 modes = 2 themes
> **Architecture**: Two-dimensional (brand × mode)
> **Default**: `lipi-default-light`
> **Last Updated**: May 3, 2026 — Phase 2 Sub-step 2.0 (A2: danger states added)
> (Phase 1 reconciliation preserved. All token values reconciled against production admin.css.
>  Phase 2.0 amendments tracked in `docs/CHANGE-LOG.md` "v1.0 — AMENDMENTS".)

## ARCHITECTURE OVERVIEW

LiPi HIS uses a **two-dimensional theme model**:

```
                  ┌─────────────────────────┐
                  │   LIGHT MODE   DARK MODE│
   ┌──────────────┼─────────────────────────┤
   │ LIPI DEFAULT │  ✓ v1.0       ✓ v1.0   │
   │ ARMOKI       │  ⏳ v1.1       ⏳ v1.1   │
   │ CLIENT 3     │  ⏳ v1.2       ⏳ v1.2   │
   └──────────────┴─────────────────────────┘
```

**Brand Theme**: Determines colors, logos, brand identity (set per clinic by admin)
**User Mode**: Light/Dark/Auto/High-contrast (set per user)

Combined: `[brand]-[mode]` → e.g., `lipi-default-light`, `armoki-dark`

## CSS VARIABLE TOKEN SYSTEM

### Three Layers (Cascade in This Order)

```
LAYER 1: STRUCTURAL (00-baseline.css)
├── Defines: spacing, sizing, typography, border-radius, layout constants
├── NO color values
├── References color tokens (e.g., var(--color-primary))
└── Always loaded

LAYER 2: BRAND (themes/brand-[name].css)
├── Defines: --brand-primary-hue, --brand-accent-hue
├── Defines logos, brand-specific assets
├── Loaded based on data-brand attribute on <body>
└── ONE brand active at a time

LAYER 3: MODE (themes/mode-[name].css)
├── Defines: actual color VALUES (resolves brand hues + mode)
├── Defines: --color-primary, --color-text, --color-bg, etc.
├── Loaded based on data-mode attribute on <body>
└── ONE mode active at a time
```

## THEME SWITCHING MECHANISM

### Activation via Data Attributes

```html
<body data-brand="lipi-default" data-mode="light">
  <!-- All theme tokens resolve based on these two attributes -->
  <!-- Switching is instant — no page reload, no FOUC if cookie is read on SSR -->
</body>
```

## THEME PROVIDER COMPONENT

### `Components/Theme/ThemeProvider.razor`

```razor
@rendermode InteractiveServer
@implements IDisposable
@inject IUserPreferenceService PrefService
@inject IClinicContextService ClinicCtx
@inject IJSRuntime JS

<CascadingValue Value="@_currentTheme" Name="CurrentTheme">
    @ChildContent
</CascadingValue>

@code {
    [Parameter] public RenderFragment? ChildContent { get; set; }

    private ThemeContext _currentTheme = new();

    protected override async Task OnInitializedAsync()
    {
        var brand = ClinicCtx.CurrentClinic?.BrandThemeId ?? "lipi-default";
        var mode  = await PrefService.GetThemeModeAsync() ?? "light";

        _currentTheme = new ThemeContext { Brand = brand, Mode = mode };

        await JS.InvokeVoidAsync("eval",
            $"document.body.setAttribute('data-brand', '{brand}')");
        await JS.InvokeVoidAsync("eval",
            $"document.body.setAttribute('data-mode', '{mode}')");
    }

    public async Task SwitchModeAsync(string newMode)
    {
        await PrefService.SetThemeModeAsync(newMode);
        _currentTheme = _currentTheme with { Mode = newMode };
        await JS.InvokeVoidAsync("eval",
            $"document.body.setAttribute('data-mode', '{newMode}')");
        StateHasChanged();
    }

    public async Task SwitchBrandAsync(string newBrand)
    {
        await PrefService.SetBrandAsync(newBrand);
        _currentTheme = _currentTheme with { Brand = newBrand };
        await JS.InvokeVoidAsync("eval",
            $"document.body.setAttribute('data-brand', '{newBrand}')");
        StateHasChanged();
    }

    public void Dispose() { /* cleanup if needed */ }
}

public record ThemeContext
{
    public string Brand { get; init; } = "lipi-default";
    public string Mode  { get; init; } = "light";
}
```

### Usage in App.razor

```razor
<CascadingAuthenticationState>
    <ThemeProvider>
        <Router AppAssembly="@typeof(App).Assembly">
            <!-- ... -->
        </Router>
    </ThemeProvider>
</CascadingAuthenticationState>
```

## DATABASE SCHEMA ADDITIONS

### New Table: `master.brand_themes`

Brand themes are stored as rows, not hardcoded CHECK constraint values.
Adding a new client brand = `INSERT` row + add CSS file. No migration required.

```sql
-- Run on: MASTER database (lipi_master)
CREATE TABLE IF NOT EXISTS master.brand_themes (
    brand_id            VARCHAR(50)   NOT NULL,
    display_name        VARCHAR(100)  NOT NULL,
    description         TEXT,
    css_file_path       VARCHAR(200)  NOT NULL,  -- path relative to wwwroot/
    logo_light_url      VARCHAR(200),
    logo_dark_url       VARCHAR(200),
    is_active           BOOLEAN       NOT NULL DEFAULT TRUE,
    is_deprecated       BOOLEAN       NOT NULL DEFAULT FALSE,
    deprecated_at       TIMESTAMPTZ,
    deprecation_reason  TEXT,
    sort_order          INTEGER       NOT NULL DEFAULT 100,
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),

    CONSTRAINT pk_brand_themes PRIMARY KEY (brand_id),
    CONSTRAINT chk_brand_themes_deprecation
        CHECK (
            (is_deprecated = FALSE AND deprecated_at IS NULL)
            OR (is_deprecated = TRUE  AND deprecated_at IS NOT NULL)
        )
);

CREATE INDEX IF NOT EXISTS idx_brand_themes_active_sorted
    ON master.brand_themes(sort_order)
    WHERE is_active = TRUE AND is_deprecated = FALSE;

-- Seed v1.0 brand
INSERT INTO master.brand_themes
    (brand_id, display_name, description, css_file_path,
     logo_light_url, logo_dark_url, sort_order)
VALUES
    ('lipi-default',
     'LiPi Default',
     'Standard LiPi navy + gold theme — imagiQa product baseline. '
     'Navy (#0F2D5E) primary with gold (#C49A22) accent.',
     'themes/brand-lipi.css',
     '/images/logos/lipi-logo.svg',
     '/images/logos/lipi-logo-dark.svg',
     1)
ON CONFLICT (brand_id) DO NOTHING;
```

### `master.clinics.brand_theme_id` — FK to brand_themes

```sql
ALTER TABLE master.clinics
    ADD COLUMN IF NOT EXISTS brand_theme_id VARCHAR(50) NOT NULL DEFAULT 'lipi-default';

CREATE INDEX IF NOT EXISTS idx_clinics_brand_theme_id
    ON master.clinics(brand_theme_id);

-- FK replaces the CHECK constraint approach — new brands need no migration
ALTER TABLE master.clinics
    ADD CONSTRAINT fk_clinics_brand_theme_id
    FOREIGN KEY (brand_theme_id)
    REFERENCES master.brand_themes(brand_id)
    ON UPDATE CASCADE   -- brand_id rename cascades automatically
    ON DELETE RESTRICT; -- cannot delete a brand while clinics use it
```

### New Table: `identity.user_preferences`

```sql
-- Run on: each CLINIC database (in identity schema)
CREATE TABLE IF NOT EXISTS identity.user_preferences (
    user_id     UUID        PRIMARY KEY,   -- FK to master.platform_users.user_id (logical, no physical FK across DBs)
    theme_mode  VARCHAR(20) NOT NULL DEFAULT 'light',
    density     VARCHAR(20) NOT NULL DEFAULT 'compact',
    font_size   VARCHAR(20) NOT NULL DEFAULT 'standard',
    language    VARCHAR(10) NOT NULL DEFAULT 'en',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT chk_user_pref_theme_mode
        CHECK (theme_mode IN ('light', 'dark', 'auto', 'high-contrast')),
    CONSTRAINT chk_user_pref_density
        CHECK (density IN ('comfortable', 'compact', 'spacious')),
    CONSTRAINT chk_user_pref_font_size
        CHECK (font_size IN ('standard', 'larger'))
);

CREATE TRIGGER tr_user_preferences_updated
    BEFORE UPDATE ON identity.user_preferences
    FOR EACH ROW
    EXECUTE FUNCTION update_modified_column();
```

## ADDING NEW THEMES (v1.1+)

To onboard a new client brand (e.g., Armoki) — **no schema migration required**.

### Step 1 — Insert brand row (data operation only)
```sql
INSERT INTO master.brand_themes
    (brand_id, display_name, description, css_file_path,
     logo_light_url, logo_dark_url, sort_order)
VALUES
    ('armoki', 'Armoki',
     'Armoki cancer hospital brand — green primary.',
     'themes/brand-armoki.css',
     '/images/logos/armoki-logo.svg',
     '/images/logos/armoki-logo-dark.svg', 2)
ON CONFLICT (brand_id) DO NOTHING;
```

### Step 2 — Create CSS file
Create `wwwroot/themes/brand-armoki.css`. Override only tokens that differ from `lipi-default`:
```css
/* themes/brand-armoki.css — Armoki brand overrides */
[data-brand="armoki"][data-mode="light"] {
  --color-primary:       #1B5E20;
  --color-primary-hover: #2E7D32;
  --color-accent:        #FFB300;
}
[data-brand="armoki"][data-mode="dark"] {
  --color-primary:       #66BB6A;
  --color-accent:        #FFD54F;
}
```

### Step 3 — Add to ThemeContextService allowlist
```csharp
// src/LiPi.Web/Services/ThemeContextService.cs
private static readonly HashSet<string> ValidBrands =
    new() { "lipi-default", "armoki" };  // expand as brands are added
```

### Step 4 — Assign the brand to a clinic
```sql
UPDATE master.clinics
   SET brand_theme_id = 'armoki'
 WHERE id = '<clinic-uuid>';
```

No app restart required. The CSS cascade already loads all brand files; the `data-brand` attribute on `<body>` activates the correct one.

## SECURITY CONSIDERATIONS

- Theme preferences are **NOT PHI** — safe to store in cookie and DB
- Theme switching JS must not allow XSS — never accept arbitrary CSS from user input
- Validate: `theme_mode` and `brand_theme_id` values against allowlist before saving

```csharp
// In UserPreferenceService (or ThemeContextService)
private static readonly HashSet<string> ValidModes =
    new() { "light", "dark", "auto", "high-contrast" };

private static readonly HashSet<string> ValidBrands =
    new() { "lipi-default" };  // Expand as new brands are added in v1.1+

public async Task SetThemeModeAsync(string mode)
{
    if (!ValidModes.Contains(mode))
        throw new ArgumentException($"Invalid theme mode: {mode}");
    // ... save to DB and cookie
}

public async Task SetBrandAsync(Guid clinicId, string brand)
{
    if (!ValidBrands.Contains(brand))
        throw new ArgumentException($"Invalid brand: {brand}");
    // ... save to master.clinics
}
```

- **Audit**: Log theme changes via `IAuditService` using `AuditActions.USER_THEME_CHANGED`
- Theme preferences are NOT PHI — no phi_access_log entry needed, but audit_events entry is good practice
