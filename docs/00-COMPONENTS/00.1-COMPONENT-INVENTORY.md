## VARIANTS BREAKDOWN

For estimating, here's variant detail per component:

### LipiButton (5 variants × 4 states = 20 visual states)
- Variants: primary, secondary, danger, ghost, icon-only, link
- States: default, hover, focus, active, disabled, loading
- Sizes: small (28px), medium (32px), large (40px)

### LipiTextBox (5 input types × 5 states)
- Types: text, email, tel, number, password, search
- States: default, focus, error, disabled, readonly
- With/without: prefix icon, suffix icon, clear button

### LipiCombo
- Searchable yes/no
- Multi-select yes/no (technically becomes LipiMultiSelect)
- Options can have: icon, sub-text, group separators
- Loading state, empty state, error state

### LipiTable
- Columns: text, number, date, status-strip, action
- Row states: default, hover, selected, disabled
- Sortable columns: yes/no per column
- Pagination: server-side or client-side
- Empty state, loading state (skeleton rows)

## STORAGE & STATE

### Component-Level State
Each component manages its own state via Blazor parameters and `@bind`.

### Global State
- **Theme**: `data-brand` and `data-mode` on `<body>` (set once, applies everywhere)
- **Toast queue**: Singleton service `IToastService` (used by `LipiToast`)
- **Modal stack**: Singleton service `IModalService` (used by `LipiModal`)
- **Loading state**: Per-component, no global

### User Preferences (Persisted)
Stored in `clinic.identity.user_preferences`:
- `theme_mode` (light/dark/auto/high-contrast)
- `density` (comfortable/compact/spacious)
- `font_size` (standard/larger)
- `language` (en/hi/etc.)

## ACCESSIBILITY CHECKLIST

Every component MUST:
- [ ] Keyboard navigable (Tab, Enter, Escape, arrow keys where applicable)
- [ ] ARIA labels (`aria-label`, `aria-describedby`, `aria-required`, `aria-invalid`)
- [ ] Focus visible (3px outline, theme-aware)
- [ ] Screen reader friendly (proper semantic HTML)
- [ ] Color contrast WCAG AA (4.5:1 text, 3:1 UI components)
- [ ] Touch targets ≥ 44×44px on mobile
- [ ] Works without mouse
- [ ] Works without color (status strips also have icon/text indicator)

## TESTING STRATEGY

For each component:

1. **Visual regression**: Screenshot test in light + dark mode
2. **Accessibility**: Run axe-core / Lighthouse a11y audit
3. **Interaction**: Selenium tests for keyboard + mouse + touch
4. **Theme switch**: Verify no flash of unstyled content
5. **Performance**: 100 instances on a page (LipiTable rows)

See `test-automation-guide.md` for framework.
