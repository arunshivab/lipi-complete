## OVERVIEW

`LipiButton` is the foundation interactive control for the LiPi HIS UI.
It ships with 5 visual variants × 3 sizes × 6 states, full keyboard and
screen-reader support, and built-in confirmation flow for destructive
actions. It consumes theme tokens exclusively — no hardcoded colors —
so both light and dark modes are supported automatically.

**Companion components** (also covered by this spec):

- `LucideIcon` — string-name → inline SVG resolver (29 icons in v1.0)
- `LipiButtonSpinner` — size-matched circular spinner used during load

## API SURFACE

13 parameters on `LipiButton.razor`:

| Parameter | Type | Default | Notes |
|---|---|---|---|
| `ChildContent` | `RenderFragment?` | `null` | Button label. `null` = icon-only mode (requires `Icon` + `AriaLabel`). |
| `Size` | `ButtonSize` | `Medium` | `Small` / `Medium` / `Large`. |
| `Variant` | `ButtonVariant` | `Primary` | Non-nullable. 5 values: `Primary`, `Secondary`, `Danger`, `Ghost`, `Link`. |
| `Icon` | `string?` | `null` | Lucide icon name for left position (or alone in icon-only mode). v1.0: Lucide names only. |
| `IconRight` | `string?` | `null` | Lucide icon name for right position. Ignored when icon-only. |
| `OnClick` | `EventCallback<MouseEventArgs>` | — | Click handler. Fires after optional confirm. No-op when `Disabled` or `IsLoading`. |
| `Disabled` | `bool` | `false` | `opacity: 0.5`, `cursor: not-allowed`, no interaction. |
| `IsLoading` | `bool` | `false` | Spinner replaces left icon. Text + right icon remain visible (no layout shift). Button disabled, `aria-busy="true"`. **Parent-controlled**. |
| `ConfirmMessage` | `string?` | `null` | If set, shows confirmation dialog before `OnClick` fires. v1.0 uses `window.confirm()`; v1.1+ may swap to `LipiConfirmDialog` without changing this parameter's API. |
| `FullWidth` | `bool` | `false` | `width: 100%` (for form layouts). |
| `Type` | `string` | `"button"` | HTML button type: `"button"`, `"submit"`, `"reset"`. |
| `AriaLabel` | `string?` | `null` | Screen reader label. **REQUIRED** for icon-only buttons (throws `ArgumentException` otherwise). |
| `Class` | `string?` | `null` | **Append-only.** Layout utilities only (margin, alignment). **Never** for visual styling. |

### Derived behavior

- `IsIconOnly` = `ChildContent == null && !string.IsNullOrEmpty(Icon)`
- `EffectiveDisabled` = `Disabled || IsLoading`
- `IconSize` = 14 / 16 / 18 px matching `Size`
- Icon-only mode → square sizing (width = height = 28 / 32 / 40 px)
- Spinner size = matches `IconSize`; animation `0.6s linear infinite`; `currentColor`

## VARIANTS

5 visual variants. All consume theme tokens — both modes supported automatically.

### Primary

Filled brand color. Default action on a page (Save, Submit, Continue).

| Aspect | Value |
|--------|-------|
| Background | `var(--color-primary)` |
| Text       | `var(--color-text-inverse)` |
| Border     | none |
| Shadow (default) | `var(--sh-sm)` |
| Shadow (hover)   | `var(--sh-md)` |
| Hover bg   | `var(--color-primary-hover)` |
| Focus ring | `0 0 0 3px var(--color-primary-pale)` |

```razor
<LipiButton Variant="ButtonVariant.Primary" Icon="save" OnClick="SavePatient">
    Save Patient
</LipiButton>
```

**When to use**: One per form/section. The "main thing the user is here to do".

### Secondary

Transparent background with 1px border. Pairs with Primary for cancel/back actions.

| Aspect | Value |
|--------|-------|
| Background | `transparent` (blends with container) |
| Text       | `var(--color-text-primary)` |
| Border     | `1px solid var(--color-border-default)` |
| Hover bg   | `var(--color-bg-hover)` |
| Hover border | `var(--color-border-strong)` |
| Focus ring | `0 0 0 3px var(--color-primary-pale)` |

```razor
<LipiButton Variant="ButtonVariant.Secondary" OnClick="Cancel">Cancel</LipiButton>
```

**Why transparent**: Secondary buttons appear on cards, toolbars, modals,
and page bodies. A white fill would create visible seams against the
container's surface. Transparent inherits the container's background
naturally.

**When to use**: Companion to Primary (Cancel, Back). Standalone secondary
actions that aren't destructive.

### Danger

Filled red. Reserved for destructive actions (Delete, Terminate, Lock).

| Aspect | Value |
|--------|-------|
| Background | `var(--color-danger)` (red-600 in light mode after A11) |
| Text       | `var(--color-text-inverse)` |
| Border     | none |
| Shadow (default) | `var(--sh-sm)` |
| Shadow (hover)   | `var(--sh-md)` |
| Hover bg   | `var(--color-danger-hover)` (red-700) |
| Focus ring | `0 0 0 3px var(--color-danger-pale)` |

```razor
<LipiButton Variant="ButtonVariant.Danger"
            Icon="trash"
            ConfirmMessage="Delete this record? This cannot be undone."
            OnClick="DeleteRecord">
    Delete Record
</LipiButton>
```

**When to use**: Destructive operations only. Always pair with `ConfirmMessage`.

**Note on color ladder**: After Phase 2.1 visual review (A11), the Danger
ladder shifted one notch deeper from the Tailwind defaults
(red-500/600/700) to red-600/700/800. The change reduces eye strain for
clinical staff who encounter destructive actions throughout shifts.

### Ghost

Transparent with no border. For low-emphasis secondary actions, especially
icon-only buttons (close, more-options, settings).

| Aspect | Value |
|--------|-------|
| Background | `transparent` |
| Text       | `var(--color-text-primary)` |
| Border     | none |
| Hover bg   | `var(--color-bg-hover)` |
| Focus ring | `0 0 0 3px var(--color-primary-pale)` |

```razor
<LipiButton Variant="ButtonVariant.Ghost" Icon="x" AriaLabel="Close" />
```

**When to use**: Toolbar buttons, modal close, dropdown triggers, table
row action icons.

### Link

Text styled as an inline link. No fill, no border, no shadow. Inherits
container line-height (no fixed height).

| Aspect | Value |
|--------|-------|
| Background | `transparent` |
| Text       | `var(--color-primary)` |
| Border     | none |
| Padding    | `0` (no min-width) |
| Height     | `auto` |
| Hover      | `text-decoration: underline` |
| Active     | `color: var(--color-primary-hover)` |

```razor
<LipiButton Variant="ButtonVariant.Link" OnClick="ShowMore">Show all 24 results</LipiButton>
```

**When to use**: Inline navigation, "show more", "view all", "learn more"
links inside prose or compact UI. Not for primary actions.

## STATES

All states honor `:not(:disabled)` so disabled buttons don't react to hover/active.

| State | Trigger | Visual |
|-------|---------|--------|
| Default | resting | Variant base styling |
| Hover | mouse over | `--color-*-hover` bg + `--sh-md` (filled variants only) |
| Active | mousedown / Enter held | `inset 0 1px 2px rgba(0, 0, 0, 0.10)` overlay; no scale transform |
| Focus | keyboard navigation | `0 0 0 3px <pale>` ring on `:focus-visible` only (mouse clicks don't show ring) |
| Disabled | `Disabled=true` or `IsLoading=true` | `opacity: 0.5`, `cursor: not-allowed`, shadow removed, no hover/active reaction |
| Loading | `IsLoading=true` | Left icon replaced by spinner; text and right icon remain visible; `cursor: wait`; `aria-busy="true"` |

### Loading contract

The loading state is **width-preserving by design**. Per design package:

- The left icon slot becomes the spinner (or shows the spinner if no left icon was set)
- Text content remains visible
- Right icon (if set) remains visible
- Button stays disabled until parent sets `IsLoading=false`

This contract eliminates layout shift mid-action and keeps the button's
identity visible while the operation runs.

```razor
@* Parent handles the IsLoading toggle around the async work *@
<LipiButton Variant="ButtonVariant.Primary"
            Icon="save"
            IsLoading="@_isSaving"
            OnClick="SaveAsync">
    Save Changes
</LipiButton>

@code {
    private bool _isSaving;

    private async Task SaveAsync()
    {
        _isSaving = true;
        StateHasChanged();          // force immediate render so spinner appears before await
        await DoTheSaveAsync();
        _isSaving = false;
    }
}
```

## ICON SYSTEM

### LucideIcon component

`LucideIcon` is a pure name → SVG resolver. Pass a Lucide icon name as
`Name`; the component renders the inline SVG with `currentColor` and
configurable size.

```razor
<LucideIcon Name="save" Size="16" />
```

| Parameter | Type | Default | Notes |
|---|---|---|---|
| `Name` | `string` | `""` | **EditorRequired**. Lucide icon name (e.g. `"check"`, `"trash"`). IDE warns if omitted. |
| `Size` | `int` | `16` | Pixel size; SVG renders at width = height = `Size`. |
| `CssClass` | `string?` | `null` | Optional class on the `<svg>` element. |

LucideIcon paints with `currentColor`, `stroke-width: 2`,
`stroke-linecap: round`, `stroke-linejoin: round` — matching Lucide's
default visual style.

### v1.0 starter icon set (29 icons)

| Group | Icons |
|-------|-------|
| Universal (6) | `check`, `x`, `plus`, `minus`, `search`, `settings` |
| Navigation (6) | `arrow-left`, `arrow-right`, `chevron-down`, `chevron-up`, `chevron-left`, `chevron-right` |
| Actions (6) | `edit`, `trash`, `save`, `download`, `upload`, `copy` |
| Feedback (5) | `alert-triangle`, `alert-circle`, `check-circle`, `info`, `help-circle` |
| HIS-specific (6) | `user`, `calendar`, `clock`, `lock`, `more-horizontal`, `bell` |

### Adding new icons

The icon library is a private static `Dictionary<string, string>` named
`Icons` inside `LucideIcon.razor`. To add an icon:

1. Find the SVG content (inner elements) on lucide.dev
2. Add a new entry to the `Icons` dictionary inside `LucideIcon.razor`:
   `["icon-name"] = """<inner svg elements>""",`
3. Stay within the 24×24 viewBox; rely on `stroke="currentColor"`

### Missing icon fallback

When `LucideIcon` receives a name not in the dictionary:

- Renders an HTML comment: `<!-- LucideIcon: 'name' not found in dictionary -->`
- On first render, calls `console.warn` via JSInterop pointing developer to the `Icons` dictionary in `LucideIcon.razor`

The button silently shrinks to text-only — no broken icon glyph appears.

## ACCESSIBILITY

### AriaLabel — hard requirement for icon-only mode

When `ChildContent` is null and `Icon` is set, the component is in
icon-only mode and **`AriaLabel` is mandatory**. Missing it throws
`ArgumentException` at `OnParametersSet`:

```text
LipiButton: AriaLabel is required when in icon-only mode
(ChildContent null + Icon set). WCAG 2.1.4.6 / SC 4.1.2 compliance.
```

This is a deliberate "loud failure" — silent accessibility breaks are
unacceptable in HIPAA-regulated software. The exception surfaces the
mistake during development rather than shipping a screen-reader-broken
button to clinical staff.

### Focus visibility

Focus rings appear only on `:focus-visible`. Mouse clicks do not show the
ring; keyboard `Tab` navigation does. This matches the OS-native
expectation and avoids the "ring shows on every click" anti-pattern.

The ring is `0 0 0 3px var(--color-primary-pale)` for non-Danger variants
and `var(--color-danger-pale)` for the Danger variant — visible on both
light and dark backgrounds.

### Loading state

When `IsLoading=true`, the button:

- Sets `aria-busy="true"` so screen readers announce the busy state
- Becomes disabled, blocking re-clicks
- Keeps the visible text label (no layout shift, no content disappearance)

### Keyboard interaction

Native `<button>` semantics are preserved. `Enter` and `Space` activate;
`Tab` / `Shift+Tab` navigate. The component does not intercept or
override keyboard events.

### Standards referenced

- WCAG 2.1.4.6 — Contrast (Enhanced)
- WCAG 4.1.2 — Name, Role, Value (icon-only AriaLabel requirement)
- WCAG 2.4.7 — Focus Visible (`:focus-visible` ring)

```razor
            Icon="trash"

            OnClick="Delete">
```

### 3. Async save with loading state

```razor
<LipiButton Variant="ButtonVariant.Primary"
            Icon="save"
            IsLoading="@_saving"
            OnClick="SaveAsync">
    Save Changes
</LipiButton>

@code {
    private bool _saving;

    private async Task SaveAsync()
    {
        _saving = true;
        StateHasChanged();
        await _service.SaveAsync(_model);
        _saving = false;
    }
}
```

```razor

```



## THEME INTEGRATION

LipiButton consumes only theme tokens. Both light and dark modes are
supported automatically by the active mode CSS file.

### Tokens consumed

**Color (theme-mode dependent)**:
`--color-primary`, `--color-primary-hover`, `--color-primary-pale`,
`--color-text-primary`, `--color-text-inverse`,
`--color-bg-hover`,
`--color-border-default`, `--color-border-strong`,
`--color-danger`, `--color-danger-hover`, `--color-danger-pale`

**Shadow (theme-mode dependent)**:
`--sh-sm`, `--sh-md`

**Structural (theme-agnostic)**:
`--font-ui`, `--r-sm`

### Light vs dark notes

| Token | Light | Dark |
|-------|-------|------|
| `--color-primary` | `#0F2D5E` (navy) | `#4A9BD4` (sky — lighter for dark bg) |
| `--color-primary-hover` | `#134E8C` (steel — A11) | `#5BAEE0` (sky-light) |
| `--color-primary-pale` | `#EBF5FF` (solid) | `rgba(74, 155, 212, 0.12)` (alpha) |
| `--color-danger` | `#DC2626` (red-600 — A11) | `#F85149` |
| `--color-danger-hover` | `#B91C1C` (red-700 — A11) | `#FF6B63` |
| `--color-danger-pale` | `#FEF2F2` (solid) | `#2c0f0f` (dark surface) |

### A11 amendment context

Phase 2.1 visual review shifted two color decisions in light mode:

1. Primary hover refined from cobalt (`#1B4DA0`) to steel blue (`#134E8C`) for a more clinical, less vibrant tone
2. Danger ladder shifted one notch deeper (red-600/700/800) to reduce eye strain in clinical workflows

Dark mode was reviewed and approved as-is. See CHANGE-LOG A11 for full reasoning.

## FUTURE CONSIDERATIONS (v1.1+)

These are **not part of v1.0**. Listed here so callers know what's
planned vs. what they shouldn't expect today.

### `LipiConfirmDialog` migration

The `ConfirmMessage` parameter currently invokes `window.confirm()` (native
browser modal). v1.1+ may replace the implementation with a custom
`LipiConfirmDialog` component (themeable, brand-consistent, testable).
**The `ConfirmMessage` parameter API stays stable** — callers won't need
to change anything when the migration ships.

### Lucide library expansion

The 29-icon starter set covers Phase 2.1 needs and common HIS actions.
New icons are added to the `Icons` dictionary inside `LucideIcon.razor` as
modules require them. Expected expansion: ~50–80 icons by end of Phase 6.

### RenderFragment icon override

In v1.0, `Icon` and `IconRight` are strings (Lucide names only). v1.1+
may add an `IconContent` / `IconRightContent` `RenderFragment` overload
for callers who need custom icons (PNG logos, animated SVGs, etc.). Not
planned for v1.0.

### LipiButtonGroup, LipiSplitButton

Group and split-button compositions are not yet built. They will reuse
`LipiButton` internally. Expected in Phase 4 or later if module needs
arise.
